# SDD Documentation Evaluation Repository

This repository stores documentation samples produced through the Spec-Driven Development (SDD) process, along with evaluation artifacts for a comparative study of five SDD tools: Spec Kit, OpenSpec, Kiro, Tessl, and BMAD Method.

## Purpose

The Python evaluation script is intended to analyze the SDD-produced Markdown (`.md`) files in `testing_files`. Files are organized first by study stage and then by tool. Each tool folder contains specification files produced by workflows run with that tool on different study cases. The analysis focuses on the structure and syntactic content of the Markdown files to identify topics relevant to software development; it does not aim to classify the subject matter of the study cases. The knowledge areas in the latest SWEBOK Guide (Version 4.0a) serve as the reference for topic relevance. A copy of the guide is included in [`docs/swebok-v4.pdf`](docs/swebok-v4.pdf) for convenient access and to document the reference used by this study.

The output is four Excel workbooks in `reports`, one per study stage. Each workbook contains three worksheets: all classification records for the stage; knowledge-area weights by tool; and topic weights by tool. The two weight sheets include every area and topic found, ordered by tool and then by descending percentage weight within each tool.

The script traverses the stage folders in `testing_files` and, within each stage, processes the five tool folders. Each stage is written to its own workbook in `reports`. The `Records` sheet contains `tool`, `KA`, `topic`, and `alignment`; the workbook filename identifies the stage. In the weight sheets, each KA or KA/topic's accumulated alignment is divided by that tool's total alignment for the stage. This gives each tool its own percentage distribution, independent of its number of source files. All represented KAs and topics are included, ordered by tool and then from highest to lowest percentage weight.

## Repository layout

The repository includes [`docs/swebok-v4.pdf`](docs/swebok-v4.pdf), a local copy of the SWEBOK Guide used as the study's reference. Its knowledge areas provide the basis for identifying and interpreting software development topics in the SDD specification files.

```text
.
|-- docs/swebok-v4.pdf
|-- geval.py
|-- requirements.txt
|-- testing_files/
|   |-- etapa_1/
|   |   |-- speckit/
|   |   |-- openspec/
|   |   |-- kiro/
|   |   |-- tessl/
|   |   `-- bmad_method/
|   |-- etapa_2/       # Same five tool folders
|   |-- etapa_3/       # Same five tool folders
|   `-- etapa_4/       # Same five tool folders
`-- reports/
    |-- etapa_1.xlsx   # Generated report for stage 1
    |-- etapa_2.xlsx   # Generated report for stage 2
    |-- etapa_3.xlsx   # Generated report for stage 3
    `-- etapa_4.xlsx   # Generated report for stage 4
```

Place each tool's workflow-generated specification `.md` files in the matching tool folder within the relevant stage. The workbook files are planned outputs and will be generated by the script; their detailed naming and formatting may be refined as the script is updated.

## Requirements

- Linux
- Python 3.12
- [Ollama](https://ollama.com/) running locally, with the model used by the script available (currently `qwen2.5-coder:14b`)

Install the Python dependencies from the repository root:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

## Running the evaluation

The current entry point is:

```bash
python geval.py
```

Run the evaluation with the default model and no time limit:

```bash
python geval.py
```

You can select an Ollama model and an optional total time limit in minutes:

```bash
python geval.py --model qwen2.5-coder:14b --time-limit-minutes 60
```

The script saves partial results to the current stage workbook after each Markdown file is evaluated.

## Evaluation scope

The study compares documentation produced through the SDD process with Spec Kit, OpenSpec, Kiro, Tessl, and BMAD Method. The workflows use different study cases, but the evaluation targets the structure and syntactic content of their generated Markdown specification files rather than the cases' subject matter. It examines the relative prominence of software development topics, taking the knowledge areas of the [SWEBOK Guide Version 4.0a](https://www.computer.org/education/bodies-of-knowledge/software-engineering/v4), published by the IEEE Computer Society, as its reference. The local copy in [`docs/swebok-v4.pdf`](docs/swebok-v4.pdf) makes that reference available within the repository and supports traceability of the study's topic framework. The analysis aims to characterize topic relevance; it does not claim that SWEBOK defines the SDD process. Report formats, scoring details, and input conventions may change as the evaluation script and repository structure are clarified.
